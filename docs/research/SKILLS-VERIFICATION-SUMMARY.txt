RECOMMENDATIONS FOR SKILL-BUILDER
================================================================================

ARCHITECTURE CHOICE: Use skill.json + prompt.md (NOT SKILL.md)
- Pros: Richer metadata, explicit tool declarations, template system
- Cons: Slightly more complex structure
- Why: Matches proven implementation pattern (product-owner)

IMPLEMENTATION APPROACH: Self-Contained, NOT Subagent-Based
- Pros: No unproven features, simpler testing, clearer for users
- Cons: Less context isolation
- Why: No successful subagent patterns found in codebase

STRUCTURE:
  skill-builder/
  ├── skill.json                (metadata config)
  ├── prompt.md                 (instructions)
  ├── templates/
  │   ├── SKILL_TEMPLATE.md
  │   └── skill.json_TEMPLATE.json
  ├── scripts/
  │   └── package_skill.py      (zip utility)
  └── resources/
      └── BEST_PRACTICES.md

STEP-BY-STEP WORKFLOW:
1. Gather requirements via prompts
2. Plan skill structure internally
3. Create skill files (SKILL.md or skill.json)
4. Generate templates/scripts as text
5. Package directory into ZIP using Bash or Python
6. Return ZIP artifact to user

FILE TRIGGERS:
- "help me build a skill"
- "create a new Claude skill"
- "turn this into a skill"
- "make a skill from my workflow"
