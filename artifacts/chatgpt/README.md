# ChatGPT Artifacts

This directory stores documents generated by ChatGPT before conversion to markdown or for external sharing.

## Purpose

ChatGPT excels at creating well-formatted documents in formats like:
- **DOCX** - Microsoft Word documents with rich formatting
- **PDF** - Portable documents for stakeholder sharing
- **XLSX** - Excel spreadsheets for data and tables
- **PPTX** - PowerPoint presentations (if needed)

These artifacts are temporary storage before conversion to markdown (SSOT).

## Typical Workflow

### 1. Generation Phase (ChatGPT)
```
User → ChatGPT: "Create a feature specification for user authentication"
ChatGPT → Generates formatted DOCX
User → Downloads to artifacts/chatgpt/auth-spec.docx
```

### 2. Conversion Phase
```bash
# Convert DOCX to markdown
./scripts/convert.sh docx2md artifacts/chatgpt/auth-spec.docx

# Review and edit the markdown
# artifacts/chatgpt/auth-spec.md
```

### 3. Integration Phase
```bash
# Move to appropriate /docs location
mv artifacts/chatgpt/auth-spec.md docs/specs/authentication.md

# Edit and refine in markdown
# docs/specs/authentication.md is now the source of truth
```

### 4. Cleanup Phase
```bash
# Remove artifact after successful conversion
rm artifacts/chatgpt/auth-spec.docx
```

## Supported Formats

### DOCX (Primary)
**Use for:**
- Specifications and requirements documents
- Architecture Decision Records (ADRs)
- Runbooks and procedures
- Long-form documentation

**Conversion:**
```bash
./scripts/convert.sh docx2md artifacts/chatgpt/document.docx
```

### PDF (Export Only)
**Use for:**
- Stakeholder presentations
- External sharing (clients, executives)
- Print-ready documents
- Final deliverables

**Note:** PDFs are typically exports from markdown, not primary artifacts:
```bash
# Generate PDF from markdown (if needed in future)
pandoc docs/specs/feature.md -o artifacts/chatgpt/feature.pdf
```

### XLSX (Data)
**Use for:**
- Data tables and matrices
- Comparison tables
- Budget/resource planning
- Test case matrices

**Conversion:**
- Manual (convert to markdown tables or CSV)
- Consider keeping as reference alongside markdown

### PPTX (Presentations)
**Use for:**
- Executive presentations
- Architecture diagrams
- Stakeholder reviews
- Workshop materials

**Conversion:**
- Extract key content to markdown
- Keep PPTX for visual presentations

## Naming Conventions

Use descriptive names with context:

```
# Good names
auth-spec-draft-2025-11-03.docx
user-flows-v2.docx
api-endpoints-reference.xlsx
architecture-overview.pptx

# Bad names
document.docx
new.docx
untitled.xlsx
presentation1.pptx
```

**Pattern:** `<topic>-<type>-<version/date>.<extension>`

## Conversion Best Practices

### Before Conversion
1. **Review in ChatGPT** - Ensure document is complete
2. **Download properly** - Use clear names
3. **Place in artifacts/chatgpt/** - Don't mix with other artifacts

### During Conversion
1. **Use convert.sh** - Standard conversion tool
   ```bash
   ./scripts/convert.sh docx2md artifacts/chatgpt/doc.docx
   ```

2. **Review markdown** - Check formatting preserved
   ```bash
   # Output is artifacts/chatgpt/doc.md
   cat artifacts/chatgpt/doc.md
   ```

3. **Edit as needed** - Fix any conversion issues
   - Check headings (##)
   - Verify lists and tables
   - Fix code blocks
   - Update links

### After Conversion
1. **Move to /docs** - Place in appropriate subdirectory
   ```bash
   mv artifacts/chatgpt/doc.md docs/specs/feature-spec.md
   ```

2. **Update references** - Fix any internal links
3. **Delete artifact** - Clean up DOCX after successful conversion
   ```bash
   rm artifacts/chatgpt/doc.docx
   ```

## Common Patterns

### Pattern 1: Specification Creation
```
ChatGPT → Create spec → Download DOCX → Convert → Edit in markdown → SSOT
```

**Timeline:** 1-2 hours from generation to finalized markdown

### Pattern 2: Stakeholder Document
```
Markdown exists → Generate DOCX for review → Share with stakeholders → Keep markdown as SSOT
```

**Timeline:** Generate on-demand, keep DOCX temporarily

### Pattern 3: Data Table
```
ChatGPT → Create XLSX with data → Convert to markdown table OR keep as reference
```

**Timeline:** May keep XLSX alongside markdown if complex

## Retention Policy

### Keep Temporarily When:
- Document is in active conversion workflow (< 7 days)
- Used as reference for ongoing markdown editing
- Stakeholders need specific format (DOCX/PDF)
- Contains formatting not preserved in markdown

### Delete When:
- Conversion to markdown complete and verified
- Markdown version is refined and finalized
- No longer referenced by team
- More than 30 days old with no activity

### Cleanup Commands
```bash
# List old ChatGPT artifacts
find artifacts/chatgpt/ -type f -mtime +30 ! -name "README.md" ! -name ".gitkeep"

# Delete old artifacts
find artifacts/chatgpt/ -type f -mtime +30 ! -name "README.md" ! -name ".gitkeep" -delete
```

- [ ] All headings converted correctly
- [ ] Lists and bullets preserved
- [ ] Tables formatted properly (or converted to lists if simpler)
- [ ] Code blocks use proper syntax highlighting
- [ ] Images handled (embedded or linked)
- [ ] Links are functional
- [ ] Formatting is consistent with /docs style

## Troubleshooting

### Issue: Conversion loses formatting
**Solution:** Use pandoc directly with specific options
```bash
pandoc -f docx -t markdown+pipe_tables artifacts/chatgpt/doc.docx -o output.md
```

### Issue: Tables don't convert well
**Solution:** Consider simplifying tables or using lists
```markdown
# Instead of complex table, use structured lists
## Feature Comparison
- **Feature A**
  - Capability 1: Yes
  - Capability 2: No
```

### Issue: Need to preserve exact DOCX formatting
**Solution:** Keep DOCX as reference, maintain parallel markdown
```bash
# Keep both for stakeholder needs
artifacts/chatgpt/spec.docx  # For external sharing
docs/specs/spec.md           # Source of truth
```
